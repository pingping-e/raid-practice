# Raid Practice — 설계 및 개발 인계

## 목표
World of Warcraft 신화 레이드 전체 전투를 혼자 연습하는 3D 웹 시뮬레이터. 유저 1명과 가상 공대원 19명이 협동 기믹을 수행한다. 딜 로테이션과 스킬 입력은 초기 범위에서 제외한다.

## 확정 요구사항
- 샘플 보스: 스조라크 신화. WCL zone 53, encounter 3420, difficulty 5.
- 참고 전투: https://www.warcraftlogs.com/reports/A8yxaWCNdrb1wmLh?fight=24&view=replay
- 랭킹: https://www.warcraftlogs.com/zone/rankings/53?boss=3420
- 공통 역할: 탱커 / 딜러 / 힐러. 딜러와 힐러는 밀리 / 레인지 별도 선택.
- 화면 중앙 부근의 캐릭터를 WASD, 마우스로 조작. 우클릭 카메라·방향 전환, 휠 줌, 옆걸음, 점프.
- BW 스타일 타이머, 중앙 경고, 카운트다운.
- 전체 전투 타임라인과 자동 구간 전환. 체력 기반 페이즈 진입과 딜은 생략.
- 공대원은 정해진 애니메이션 재생만 하지 않고 유저 위치와 기믹 상태에 반응.
- 조, 소킹 순서, 대상 유도, 낭종 배치·터뜨리기, 짝 기믹 사전 배정.
- 실전 대상 선정과 내 특임 대상 보장 모드 분리.
- 구간 시작, 배속, 일시정지, 동일 시드 재도전, 실패 원인과 해당 구간 재연습.
- 기능 묶음 단위로 커밋하고 푸시.

## 기믹 설계
- Ravage: 탱커 전방 공격. 비담당 인원 회피. 탱커 교대와 취약 디버프를 추후 정확히 모델링.
- Mutilate: 두 소킹 조가 교대. 실제 범위 안 인원으로 판정. 연속 중복 소킹 취약 디버프 필요.
- Tempest: 이동·반사하는 회오리와 충돌 판정.
- Fury: 가장 먼 대상 유도, 반경 8야드 안 14명 집결이 실제 충족되면 트리거. 로그의 제거 시각은 관측 결과이며 보스의 고정 자동 시전 시각이 아니다.
- Virulence: Fury 후 산개, 십자 방출과 전염, 잔류 바닥. 체인 전염과 길이 변화는 추가 구현 필요.
- Venomous Surge: 배정된 바람 반대쪽 마커에 낭종 배치. 낭종은 접촉으로 실제 폭발하고 반동과 감속을 적용해야 한다.
- Crosswinds: 방향별로 짝을 맞춰 이동, 비행 중 충돌로 밀림 상쇄. 초기 버전의 위치 기반 성공 판정은 임시다.
- Dig In: 강풍 3회. 낭종 반동으로 상쇄. 원본 로그에 강풍 세부 이벤트가 부족하므로 시간·방향을 추가 추출해야 한다.
- 스조라크는 기본 전투와 강풍 구간 반복이다. 임의로 1/2/3페를 붙이지 않는다.
- 봇: 규칙 기반 상태 머신 + 이동·장애물 회피. LLM 실시간 호출 불필요.

## 현재 구현 수준과 한계
코드를 작성했으며 JavaScript 구문 검사는 당시 통과했다.
브라우저 테스트 호출이 장시간 응답하지 않아 플레이·렌더링 검증은 하지 못했다.
봇, 범위, 물리, 지도, 카메라가 실전과 동일하다고 검증되지 않았다.
Fury는 현재 고정 시간의 집결 판정으로 단순화되어 있어 실제 조건 트리거로 교체가 필요하다.
강풍은 시간 간격과 방향을 재구성했으며 실제 물리·낭종 소모 판정 보강 필요.
역할의 전투 위치 선택 UI는 있으나 조별 배정과 근접 힐러 동작을 점검해야 한다.
실전/집중 모드 차이, 특임 세부 배정, 탱커 디버프·교대 기능 미완성.
캐릭터·보스·맵은 독자 제작 단순 3D 도형이다. WoW 원본 모델 아님.
같은 시드로 재현하되 실제 대상 규칙을 근거 없이 완전 랜덤으로 처리하지 않는다.

## 알려진 개선 필요
- 소킹 조와 파티 조를 혼동하지 말고 독립적으로 지정.
- 유저가 빠진 경우 봇이 무조건 인원을 메워 성공시키지 않도록.
- 회오리, 맹독, 콤보가 겹칠 때 봇 목표 우선순위와 경로를 안정화.
- 구간 이동 시 과거 상태를 재구축하되 피해·결과 기록 초기화, 유효 상태만 유지.
- 일시정지 중 경고음·판정·타이머 정지.
- 프레임 속도와 배속에 무관하게 일정한 시뮬레이션 스텝.
- 시나리오 JSON 입력의 숫자·형상·좌표·소스 링크 검증.
- 숨김 탭·포커스 상실 입력 해제.
- 봇 상태와 실패 원인 가시화.
- 외부 폰트 의존 줄이고 오류·WebGL 미지원 안내.
- UI 안에 과도한 기술 용어를 넣지 않되 정확도 표시는 명확히.
