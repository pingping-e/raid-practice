# Raid Practice

스조라크 신화 전체 전투를 **내 캐릭터 + 19인 규칙 기반 봇**으로 연습하는 3D 웹 앱입니다. Three.js의 독자 제작 도형을 사용합니다. 실제 WoW 지도·모델 또는 완벽한 전투 재현이 아닙니다.

## 실행

Node.js 22.12 이상(검증 환경: 24.19.0), npm이 필요합니다.

```sh
npm ci
npm run dev
```

기본 개발 포트는 5173입니다. 프로덕션 파일은 `npm run build`로 `dist/`에 만들고, `npm run preview`로 내부 확인할 수 있습니다. 정적 호스팅에서도 실행됩니다. 브라우저에 WCL 인증 정보가 필요하지 않습니다.

```sh
npm test                 # 순수 엔진 테스트 13개
npm run build           # TypeScript 검사 + 프로덕션 번들
npm run test:browser     # Chromium에서 실제 화면·조작·전체 전투 검증
```

브라우저 테스트는 `/usr/bin/chromium`을 사용합니다. 다른 실행 파일은 `CHROMIUM_PATH`로 지정하세요. Chromium이 없는 로컬 환경은 운영체제에서 Chromium을 설치하거나 Playwright 구성을 해당 브라우저에 맞추세요.

## 플레이

1. 탱커·딜러·힐러, 근접·원거리, 파티와 별도의 소킹 조를 선택합니다. 탱커는 공대 소킹 인원에서 제외됩니다.
2. Fury 유도 담당, 낭종 마커·강풍 담당 순서, 교차 강풍 짝, 시드를 정하고 **배정 적용**을 누릅니다.
3. 시작 후 WASD와 마우스로 조작합니다. A/D는 회전, Q/E는 옆걸음입니다. 우클릭 중 A/D는 옆걸음, 양쪽 마우스 버튼은 전진, 휠은 줌, Space는 점프입니다. 좌클릭 드래그는 카메라만, 우클릭 드래그는 카메라와 진행 방향을 회전합니다. 키 설정과 감도를 변경할 수 있습니다.
4. 기본 조건 모드에서 Fury는 최원거리 대상을 고릅니다. 집중 모드는 선택한 기믹의 내 대상을 보장합니다. 대상 선정과 사전 배정은 별개입니다.
5. 하단 타임라인이나 ‘출처와 구현 수준’의 **8초 전**으로 구간을 선택합니다. 과거 시뮬레이션을 고정 스텝으로 재실행해 봇·보스 방향·낭종·바닥·디버프·RNG를 복원하고 점수는 비웁니다. 이후 **계속**으로 시작합니다.
6. 전투 분석에서 실패 원인을 보고 해당 기믹 8초 전부터 반복합니다. 같은 시드는 배정과 대상 난수를 재현하며, 실제 결과에는 내 이동이 영향을 줍니다.

포커스를 잃으면 입력을 해제하고 일시정지합니다. 소리와 이동 목표를 끌 수 있습니다. 기록은 브라우저에 최대 30회 저장되며 설정과 시나리오는 JSON으로 내보내고 불러옵니다. 데스크톱 키보드·마우스 조작을 대상으로 합니다. 모바일 터치 이동은 지원하지 않습니다.

## 현재 구현

- 고정 60Hz 코어와 렌더러 분리, 0.5/1/2배속, 전체 302.375초 전투
- 2탱커·4힐러·14딜러, 파티와 소킹 별도 배정, 근접·원거리 힐러
- 유린 전방과 탱커 교대·취약, 절단 9인 교대 소킹과 중복 취약
- 이동·벽 반사 회오리와 충돌
- Fury 최원거리 선정과 실제 8yd·14인 집결 → To the Slaughter → 맹독 산개
- 맹독 십자 방출·최대 2세대 전염·잔류 바닥
- 마커 배치 낭종, 접촉 소모, 주변 8yd 반동·감속, 강풍과 자원 연계
- 교차 강풍 짝 사전 배정, 실제 비행 상대 이동·충돌 상쇄
- 방향별 강풍 3회, 담당 순서에 따른 봇 이동
- 타이머·중앙 경고·시전 바·카운트다운 음향·20인 상태 UI

**시간·반경·물리는 대부분 연습용 재구성입니다.** 특히 AI가 모든 기믹을 정확히 수행하는 수준은 아니며 서로 겹치는 위험에서 실패할 수 있습니다. 스킬·딜·힐·사망 모델은 없습니다. 피해를 기록하고 계속 연습합니다. [정확도와 제한](docs/ACCURACY.md)을 확인하세요.

## WCL 데이터 추출

현재 네트워크 정책이 `www.warcraftlogs.com` 및 공략 사이트를 차단해 원본 재조회는 수행하지 못했습니다. 환경 설정에서 해당 목적지를 허용하고 `WCL_CLIENT_ID`, `WCL_CLIENT_SECRET`을 안전하게 설정한 뒤 실행하세요. 인증값을 명령줄·Git·프론트엔드에 넣지 마세요.

```sh
npm run wcl:extract
# 필요할 때만 디버프도 수집 (추가 API 비용)
python3 tools/extract_wcl.py --debuffs --max-pages 12
# 캐시를 새로 조회할 때
python3 tools/extract_wcl.py --refresh
```

도구는 OAuth client_credentials, 25초 요청 제한, 제한된 429 재시도, 페이지 예산과 캐싱을 사용합니다. 출력 `.cache/wcl/wcl-practice.json`을 앱의 **불러오기**로 선택하세요. API 토큰은 파일에 저장하지 않고 원본 이벤트 캐시는 `.cache/wcl`에만 둡니다. `.cache`, `.env`, `dist`, `node_modules`는 Git에서 제외됩니다.

출력은 **관측 시전만 있는 별도 시나리오**입니다. Fury 디버프 해제에서 자동 성공 시각을 만들지 않습니다. API의 희소 좌표에서 원본 리플레이 경로를 얻었다고 주장하지 않습니다. 시전 ID·sourceID·GraphQL 스키마는 실제 접근 복구 후 대조해야 합니다. 이 도구의 인증 조회 성공은 아직 확인되지 않았습니다.

## 구조

- `src/engine.ts`: 순수 코어, 배정·AI 목표·이동·충돌·기믹·상태 복원
- `src/scenario.ts`: 출처와 신뢰도가 있는 타임라인 및 검증
- `src/input.ts`: 입력·바인딩·마우스 카메라 상태
- `src/view.ts`: Three.js 전장·도형·위험 표시·3인칭 카메라
- `src/main.ts`, `src/style.css`: HUD·설정·저장·분석·재생 루프
- `tools/extract_wcl.py`: 서버/개발 전용 WCL 추출
- `tests/engine.test.ts`, `tests/browser/`: 코어·브라우저 검증

다음 우선순위는 원본 WCL과 현재 신화 공략 대조, 정확한 바람·대상 정책 반영, 봇의 중첩 기믹 경로·조별 자원 계획 보강입니다. 기존 [설계 인계](docs/ARCHITECTURE-AND-HANDOFF.md)는 과거 세션 기록으로 보존하며 현재 구현 상태는 이 README와 정확도 문서를 기준으로 합니다.
